## 1. 两库分离

| 库 | 英文 | 可变？ | 谁写 | Mod |
|---|---|---|---|---|
| **定义库** | Definition | 否（改内容=改版本/Mod） | 策划档案 / 导入表 | 可覆盖、可附加 |
| **运行库** | Runtime / Save | 是 | 引擎解释器 only | 不可直接改定义 |

```
定义库 ──new game──► 运行库（存档）
   ▲                    │
   │                    │ tick / 行动 / 事件 / 对话选项
   │                    ▼
   │              apply effects（见词汇表）
   └──────── 定义永不被运行时改写 ────────┘
```

## 2. 定义库 · 表一览

与 `docs/暗潮/` 文件夹一一对应；实现时可 Markdown→YAML/JSON，**表名建议稳定**。

| 表名 | 文件夹 | 主键 | 说明 |
|---|---|---|---|
| `def_character` | `01_人物档案` | `char_id` | 身份、性情、标签；不含运行时交情 |
| `def_location` | `02_建筑档案` | `loc_id` | 时段开放、热区 |
| `def_org` | `03_组织档案` | `org_id` | 组织名片、组织层字段定义 |
| `def_stat` | `04_数值定义` | `stat_id` | 主角属性元数据、阈值 |
| `def_tick` | `04_数值定义` | `tick_id` | 日/时段自动规则 |
| `def_bond_type` | `05_关系档案` | `bond_type` | 父子/定亲/竞业… |
| `def_edge_init` | `05_关系档案` | `(from,to)` | 开局交情边 |
| `def_grudge` | `05_关系档案` | `grudge_id` | 恩怨定义、埋点、兑现窗、闪回 key |
| `def_action` | `06_行动档案` | `act_id` | 地点、时段、前置、effects |
| `def_event` | `07_事件档案` | `event_id` | 触发、选项、effects |
| `def_clue` | `08_线索档案` | `clue_id` | 线索定义与品质 |
| `def_calendar` | `09_日程表` | `(day,slot)` | 固定/自由/休息 |
| `def_ending` | `10_路线与结局` | `ending_id` | 结局条件 |
| `def_dialog` | `11_对话档案` | `dialog_id` | 节点、选项、loc_key |
| `def_item` | `12_信物与把柄` | `item_id` | 信物/把柄定义 |
| `def_finance_service` | `04_数值定义` | `service_id` | 票号/授信/分成等金融服务模板 |
| `def_loc_string` | （本地化） | `loc_key` | 文案 |

**原则：** 定义表不出现「当前好感=70」这类运行值；开局值放 `def_edge_init` / `def_stat.initial`，开局时拷贝进运行库。

## 3. 运行库 · 表一览

权威字段见 [`存档结构.md`](存档结构.md)。摘要：

| 表名 | 主键 | 说明 |
|---|---|---|
| `run_meta` | `slot_id` | 日、时段、版本、种子、**player_rank** |
| `run_stat` | `stat_id` | 主角当前数值 |
| `run_edge` | `(from,to)` | 交情分、修正、债、把柄 |

## 4. 派生字段（不存或仅缓存）

| 字段 | 来源 | 存档？ |
|---|---|---|
| `tier`（交情档） | 由 `score` 推导 | 可缓存，以 score 为准 |
| 结局是否达成 | 扫描 `def_ending` | 不预存，结算时算 |
| UI 显示名 | `def_loc_string` | 不进存档 |
| 职级称号显示 | `player_rank` + loc | 可缓存 |
| 恩怨 UI 列表 | `run_grudge` + `def_grudge` | 以 run 为准 |

## 5. Tick 管线（引擎顺序 · 锁定语义）

```
1. on_slot_enter（若换时段）
2. 若本格有固定/条件事件 → 入队 → 播完 apply effects
3. 否则玩家选行动 → apply 行动 effects
4. on_action_after
5. 扫关系触发 / 失败阈值 → 可能再入队事件
6. 若本日最后时段结束 → on_day_end
7. 写回 run_* ；推进 day/slot
```

冲突优先级：**事件 effect > 行动 effect > tick**（同字段同帧按此序叠加）。

## 7. 金融系统扩展（v0.2）

### 7.1 金融服务定义 `def_finance_service`

用于定义“票号短借 / 续借 / 汇兑 / 信用背书 / 洋行分成口径”这类稳定服务。

建议字段：

| 字段 | 说明 |
|---|---|
| `service_id` | 如 `svc_bank_loan_short` |
| `provider` | `org_*` / `char_*` |
| `service_type` | `loan` / `remit` / `credit` / `commission` |
| `require` | 前置条件 |
| `principal_rule` | 本金规则 |
| `interest_rule` | 利息或抽成规则 |
| `risk_rule` | 对嫌疑/信用/关系的影响 |
| `loc_hint` | 常驻地点，如 `loc_04` |

### 7.2 债务实例 `run_debt`

债务不是 flag，而是运行中的账。

```yaml
run_debt:
  debt_bank_short_001:
    service_id: svc_bank_loan_short
    creditor: org_bank
    principal: 15
    remaining: 15
    interest_per_day: 1
    due_day: 18
    collateral: none
    status: active
```

适用范围：

- 票号短借
- 私下借账
- 人情垫付
- 洋行预支（若后续扩）

### 7.3 组织账务实例 `run_org`

`run_org` 不只存“气血”，也可存组织层现金与压力：

```yaml
run_org:
  org_qianji:
    firm_bright: 55
    firm_dark: 40
    firm_heat: 25
    cash_bright: 60
    cash_dark: 45
    liquidity: 50
    payroll_pressure: 20
    tribute_pressure: 35
```

### 7.4 金融与关系的分工

- **现金余额**：`run_stat.stat_money`
- **债务实例**：`run_debt`
- **人情债 / 把柄**：`run_edge.debt` / `run_edge.leverage`
- **组织流水压力**：`run_org`
- **门路信用 / 背书资格**：`run_meter` + `run_flag`
