# 对话规范（设计）

> 对话也是数据：条件读运行库，选项只写 effect，文案走 `loc_key`。  
> 实现表：`def_dialog`（见 [`数据库架构.md`](数据库架构.md)）。  
> **现状**：完整对白仍在总源 V3；本规范定迁移目标。拆分目录：[`../11_对话档案/`](../11_对话档案/README.md)。

---

## 1. 节点形状

```yaml
dialog_id: dialog_e014_a_intro
event_id: E014                 # 可选挂接
speaker: char_qian_zian        # 或 narrator
loc_key: dialog.e014.a.intro   # 正文
tags: [mainline]
require: []                    # 同 effect 词汇表条件
next: dialog_e014_a_choice     # 或 null
choices:                       # 叶节点可无
  - id: A
    loc_key: dialog.e014.choice.a
    require: [...]
    effects: [...]
    next: dialog_e014_a_outro
  - id: C                    # 检定型（玩家点一次，引擎判成败）
    loc_key: dialog.e007.choice.c
    check:
      require: { key: stat_intel, op: ">=", value: 10 }
      on_pass: { effects: [...], next: dialog_e007_outro_c_ok }
      on_fail: { effects: [...], next: dialog_e007_outro_c_fail }
```

---

## 2. 规则

1. **逻辑不进句子**：不写「（好感+10）」在 loc 正文里；数值只在 `effects`  
2. **选项 ID**：事件内 `A/B/C` 或 `opt_01`；全局唯一用 `eventId_opt`  
3. **旁白**：`speaker: narrator`  
4. **已读**：可记 `run_dialog_seen`，防刷；主线关键可强制可重看  
5. **迁移顺序**：P0 高分支 → P1 洋人线 → P2 其余主线 → P3 日常短句池  
6. **检定**：`require` 锁选项可见/可选；`check` 表示点选后再判成败（如 E007C）  
7. **多结局入口**：可用 `next_by_condition`（失败优先，见 E018）  

---

## 3. 与事件文件关系

| 层 | 职责 |
|---|---|
| `07_事件档案` | 触发、选项效果、摘要（设计期可保留） |
| `11_对话档案` | 逐句节点与 loc_key（实现期权威演出） |
| `def_loc_string` | 多语言正文 |

设计期允许事件 md 里暂留摘要对白；**定稿搬迁后事件文件只留 trigger+effects+dialog 入口 id**。
