# 新增文档注册流程

> 目标：以后新增角色、事件、对话、系统文档时，所有人走同一套入口，避免漏补索引、漏挂系统、漏写覆盖关系。  
> 相关：[`内容注册总则.md`](内容注册总则.md) · [`Mod与DLC约定.md`](Mod与DLC约定.md)

---

## 1. 通用流程

任何新增内容，统一按这 6 步走：

1. **判层**：先判断它属于核心契约、系统模块、注册表还是战役实例  
2. **定 ID**：按 [`ID命名与后缀语义总表.md`](ID命名与后缀语义总表.md) 选稳定命名  
3. **定归属**：明确 `pack_id`、目录、依赖对象  
4. **写正文**：创建实际文档或条目  
5. **补注册**：写入对应注册表或主索引  
6. **补回链**：更新 README、专题入口、交叉引用

---

## 2. 新增事件

至少补这些入口：

1. `07_事件档案` 下的实际事件文件  
2. `15_注册表/事件注册表.md`  
3. 若有对白入口，补 `15_注册表/对话注册表.md`  
4. `07_事件档案/README.md`  
5. 若接入路线 / 职级 / 清算窗 / 结局，补 `15_注册表/路线与系统挂钩表.md`  
6. 若影响排期，补 `09_日程表/` 对应文档

事件文档至少回答：

- 它是谁
- 它在哪个槽位竞争
- 它和谁互斥
- 它的主结果是什么
- 它的对白入口是什么

---

## 3. 新增对话

至少补这些入口：

1. `11_对话档案` 下的实际对白文件  
2. `15_注册表/对话注册表.md`  
3. `11_对话档案/README.md`  
4. 若是某事件变体，回链到该事件注册条目

对话文件只负责：

- 节点
- 演出顺序
- 选项
- 局部演出逻辑

不要在对话里重复承载整套事件级主结算。

---

## 4. 新增角色 / 地点 / 组织 / 线索 / 物品

至少补这些入口：

- 对应目录下的实际文件
- 对应目录的 README 或索引表
- 若被事件、对话、系统多处引用，补交叉文档

新增这类对象时，重点不是注册槽位，而是保证：

- ID 稳定
- 被谁引用明确
- 不与现有对象语义重叠

---

## 5. 新增系统文档

例如新增“声望系统”“新清算窗”“新身份体系”时：

1. 先放进系统模块层，而不是直接写进单个事件  
2. 补一份系统 README 或规则说明  
3. 在 `15_注册表/路线与系统挂钩表.md` 标明接入点  
4. 若需要新增字段或枚举，先更新核心契约文档  

---

## 6. 新增 MOD / DLC / 扩展包

至少补这些入口：

1. `modinfo.yaml` 或等价包清单  
2. `15_注册表/内容包注册表.md`  
3. 本包提供的事件 / 对话 / 覆盖条目  
4. 必要的依赖和 `overrides`

若一个包只想改对白，不应直接覆盖整段事件；优先登记为对白变体。

---

## 7. 提交前检查

新增或修改内容前，至少确认这 7 项：

1. ID 是否稳定且符合命名规则  
2. 是否明确归属 `pack_id`  
3. 是否补了对应注册表  
4. 是否补了目录 README  
5. 是否补了必要回链  
6. 是否意外重复了现有逻辑  
7. 是否误把历史总源当成当前权威入口
