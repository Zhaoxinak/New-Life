# ID 命名与后缀语义总表

> 目标：统一《暗潮》内容 ID、事件后缀、变体和扩展命名语义，避免未来多人扩写、DLC、MOD 时冲突。  
> 相关：[`旗标与命名.md`](旗标与命名.md) · [`Mod与DLC约定.md`](Mod与DLC约定.md)

---

## 1. 基础前缀

| 前缀 | 用途 | 例 |
|---|---|---|
| `char_*` | 人物 | `char_lin_ruisheng` |
| `loc_*` | 地点 | `loc_01` |
| `org_*` | 组织 | `org_qianji` |
| `stat_*` | 属性 | `stat_money` |
| `act_*` | 行动 | `act_01` |
| `clue_*` | 线索 | `clue_suspicious_manifest` |
| `item_*` | 信物 / 把柄 | `item_qing_letter` |
| `dialog_*` | 对话节点 | `dialog_e020_start` |
| `grudge_*` | 恩怨账 | `grudge_zian_slight` |
| `flag_*` | 过程旗 | `flag_bradley_invite` |
| `route_*` | 路线旗 | `route_endure` |

事件、meter、rank 等沿用既有规则，详细见 [`旗标与命名.md`](旗标与命名.md)。

## 2. 事件主编号

| 前缀 | 含义 |
|---|---|
| `E` | 主线事件 |
| `M` | 朝账场次事件 |
| `R` | 随机 / 条件事件 |
| `F` | 失败 / 终止事件 |

原则：

1. 主编号用于表达事件主族，不直接表达所有细分变体。  
2. 事件的叙事顺序、文件排序、注册顺序允许不同，但**注册表必须稳定**。  
3. 文档 README 可按阅读顺序排序，机器主索引应按稳定字段排序。

## 3. 后缀语义

从本轮重构起，后缀尽量收紧成以下口径。

### 大写字母后缀：路线 / 槽位主变体

用于同一事件槽位下、拥有不同主爽或路线归属的并列变体。

例：

- `E020`：章二升阶主槽位的默认 / A 线版本
- `E020B`：同槽位的 B 线主变体
- `E020C`：同槽位的 C 线主变体

适用场景：

- 路线主爽变体
- 同一章位的并列主事件
- 不同阵营 / 不同体系下的正式主版本

### 小写字母后缀：临时重入 / 延迟重播 / 技术性再入

用于同一事件对象的时间补偿版、延迟版、重入版，不表达新路线。

例：

- `E010b`：`E010` 的推迟重入版

适用场景：

- 错过原时段后的补播
- 条件未达成后的延迟版本
- 不足以视为独立路线主变体的技术性分支

### 禁止混用

以下情况不应继续混用同一种后缀：

- 用大写字母同时表示“路线变体”和“结局分支结果”
- 用小写字母表示“新路线内容”
- 用后缀代替明确的注册表字段

换句话说，**后缀是辅助识别，不替代注册表里的 `slot_id / route_tags / variant_of / entry_kind`。**

## 4. 对话 ID

对话节点继续沿用：

- `dialog_e020_start`
- `dialog_r010_start`
- `dialog_f003_start`

若未来需要更细变体，优先在注册表中区分 `variant_of`，而不是无限在文件名上堆叠语义。

建议：

- 文件名可继续沿用 `DIALOG_E020.md`
- 变体对白可在注册表中声明是 `E020` 的特定入口或特定包提供的变体

## 5. 扩展包命名

原版文档内容可以继续保留原风格。  
扩展包必须至少有稳定的 `pack_id`。

推荐规则：

1. 原版内容不改历史 ID  
2. 扩展包用 `pack_id` 表达来源  
3. 是否覆盖原版，由 `overrides` 显式声明  

示例：

```yaml
pack_id: dlc_jinmen
event_id: E020D
overrides: []
```

或：

```yaml
pack_id: mod_altliu
event_id: E020
overrides:
  - E020
```

在真正数据导出阶段，可进一步把逻辑唯一键提升为 `pack_id + object_id` 组合。

---

## 6. 目录与文件命名

原则：

1. 目录名服务于阅读与排序  
2. 注册表字段服务于接入与校验  
3. 文件名不应承担过多业务语义  

因此：

- 事件 README 可按剧情阅读顺序排列
- 事件主索引应按 `event_id / slot_id / chapter / pack_id` 排列
- 文件名允许保留当前读写习惯，但系统语义以后以注册表为准

---

## 7. 当前迁移口径

在不大规模改名的前提下，先执行这 4 条：

1. 保留现有 `E020B / E021C / E010b` 文件名  
2. 在注册表中补清楚它们是“路线变体”还是“重入变体”  
3. 后续新内容尽量按本表收紧语义  
4. 若未来统一重命名，先迁移注册表，再迁移文件名
