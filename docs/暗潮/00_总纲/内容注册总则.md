# 内容注册总则

> 目标：把《暗潮》的新增、覆盖、挂钩内容统一纳入可追踪入口，避免“文档写了，但系统不知道它存在”。  
> 相关：[`数据库架构.md`](数据库架构.md) · [`Mod与DLC约定.md`](Mod与DLC约定.md) · [`新增文档注册流程.md`](新增文档注册流程.md)

---

## 1. 单一真源

从扩展化重构开始，内容分成四层：

1. **核心契约层**：schema、effect、存档、命名、表现边界  
2. **系统模块层**：路线、职级、清算、数值等可复用玩法规则  
3. **注册表层**：事件、对话、内容包、系统挂钩的统一索引  
4. **战役实例层**：角色、组织、事件、对话、线索、日程等《暗潮》本体内容  

原则：**文档可以说明，注册表负责声明，核心契约负责裁决。**

---

## 2. 什么叫“注册”

一个对象被视为已接入，至少同时满足：

1. 有稳定 ID  
2. 有归属层级  
3. 有归属 `pack_id`  
4. 在对应主注册表出现  
5. 被需要它的系统入口引用

只写在文档里、不进注册表，视为“草稿存在，但系统未接入”。

---

## 3. 哪些对象必须注册

以下内容一律必须注册：

- 事件
- 对话入口
- 内容包
- 路线挂钩
- 结局挂钩
- 新增系统窗口

以下内容默认走原档案 + 总表，不强制单独注册，但若跨包引用频繁，建议补索引：

- 角色
- 地点
- 组织
- 线索
- 物品

---

## 4. 注册表分工

| 注册表 | 负责什么 |
|---|---|
| `事件注册表` | 哪些事件存在、属于哪个槽位、和谁互斥、由哪份对白入口承接 |
| `对话注册表` | 哪些对话入口存在、归属于哪个事件、是不是某个变体 |
| `内容包注册表` | 哪些包存在、依赖什么、覆盖什么 |
| `路线与系统挂钩表` | 哪些路线、职级、清算窗、结局条件与事件槽位接起来 |

---

## 5. 覆盖与追加

### 追加

新建对象，不替换旧对象。  
适合新增章节、角色、随机事件、变体对白。

### 挂钩

不替换对象本体，只在已有系统入口上追加接入。  
适合新增章二主爽、额外清算窗、路线分支口。

### 覆盖

替换原对象或原入口逻辑。  
必须显式登记 `overrides`。

原则：**先追加，再挂钩，最后才覆盖。**

---

## 6. 责任边界

| 层 | 可以做什么 | 不该做什么 |
|---|---|---|
| 核心契约层 | 定 schema、定命名、定 effect 白名单 | 写某个具体事件的私有规则 |
| 系统模块层 | 定玩法语义、定义挂钩点 | 直接承担具体战役排期 |
| 注册表层 | 定对象存在性与接入关系 | 写长篇散文式剧情说明 |
| 战役实例层 | 写具体人物、事件、对白、日程 | 重新定义全局命名或扩展规则 |

---

## 7. 当前执行口径

在机器化导出完全落地前，Markdown 仍可承载设计内容；但以下几件事必须开始收紧：

1. 事件与对话的主入口关系必须有单独索引  
2. 路线裁决与互斥关系必须可在注册表追踪  
3. 任何新增包都必须先声明 `pack_id`  
4. 历史总源不再作为并行权威
