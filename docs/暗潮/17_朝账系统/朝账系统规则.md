# 朝账系统规则

> 本文件定义「前堂朝账」作为**可复用系统模块**如何工作，不绑定钱记具体人名。  
> 《暗潮》实例映射见 [`暗潮朝账挂点.md`](暗潮朝账挂点.md)。

---

## 1. 系统要解决什么

朝账不是额外剧情，而是把以下五条线收进同一个仪式：

| 线 | 朝账中的落点 |
|---|---|
| 职级 | ③ 仪典升降（升职四件套 / 降职公告） |
| **序位** | ② 汇报排名播报；③ 仅池内前列可升（见 [`../13_职级档案/职级竞争与排名.md`](../13_职级档案/职级竞争与排名.md)） |
| 人心 | **④ 诸人建言**（发言 / 沉默 / 附议；竞争者常踩你） |
| 目标感 | ⑥ 摊派差事 → 本周 HUD 任务清单 |
| 方针 | ⑤ 东家定调 → 吸收建言后拍板 |
| 信息差 | ①② 旁听碎片 vs 堂内全量 |

---

## 2. 周期与槽位

| 项 | 规则 |
|---|---|
| 周期 | 每 **7 日** 一次 |
| 朝账日判定 | `day % 7 == 1`（Day 1、8、15、22、29、36、43、50…） |
| 占用 | `morning` + 组织主场景（钱记 = `loc_01`） |
| 当天早上 | 朝账结束前 **不可自由行动** |
| 非朝账日 | `run_meeting.days_until_next` 每日 −1，至 0 时次日为朝账日 |

## 3. 单场六段式

固定顺序，玩家参与深度随 `attendance_tier` 变化：

```
① 开门点名   — 站位、缺席、谁坐堂内
② 分铺汇报   — 由高到低汇报；**播本周池内排名**
③ 仪典升降   — 池内前 N 名升职 / 降职 / 搁置
④ 诸人建言   — 有资格者逐人发言或沉默（太阁式）；详见 [诸人建言.md](诸人建言.md)
⑤ 东家定调   — 吸收建言后拍板本周方针
⑥ 摊派差事   — 写入 run_meeting.weekly_tasks
```

> **范围**：仅 **明面晋升轨**（学徒→外场→跑街）。**核心层 / 后堂** 不走朝账排队，见 [`../13_职级档案/核心层与入局捷径.md`](../13_职级档案/核心层与入局捷径.md)。

### 演出合同

完整分镜与 `MeetingStage` 见 [`朝账议场演出合同.md`](朝账议场演出合同.md)。摘要：

- 旁听：门帘后剪影 + **关键字高亮**（「跑街」「满师」「特别货」）；④ 段仅闻「谁开口 / 谁不语」  
- 建言：堂内发言者高亮；沉默显示「……」；单条宜短，可被东家截断  
- 升降：复用升职四件套演出（见 [`../00_总纲/表现层边界.md`](../00_总纲/表现层边界.md)）  
- 搁置/降职：学徒在门外听见自己名字被划掉，比单独弹窗更痛  
- 摊派：任务卡片飞入 HUD「本周差事」

## 4. 参与等级 `attendance_tier`

由 `player_rank` 与剧情旗标共同决定：

| tier | 条件 | 玩家能做什么 |
|---|---|---|
| `listen` | `apprentice` 且未 `flag_meeting_report_eligible` | 门外旁听；④ 段听建言碎片；偶被点名答一句 |
| `report` | `waichang`+，或旗标提前开汇报权 | 堂内汇报；④ 段可 **建言 / 不言** |
| `decide` | `paojie`+ | ④ 段可 **附议**；⑥ 段可向伙计摊派差事（正式版扩） |

`tier` 只影响 UI 与选项，**不替代** `player_rank` 权限定义（见 [`../13_职级档案/职级阶梯.md`](../13_职级档案/职级阶梯.md)）。

## 5. 存档 `run_meeting`

```yaml
run_meeting:
  cycle_index: 0          # 已完成朝账次数（含 M001）
  days_until_next: 7      # 距下次朝账；朝账日结束时重置为 7
  report_score: 0         # 本周汇报分 0–100；朝账前夜结算后写入
  attendance_tier: listen # listen | report | decide
  weekly_tasks:           # 当前周期差事
    - id: task_tidy_manifest
      label_key: meeting.task.tidy_manifest
      target: 2
      progress: 0
      weight: 15          # 计入汇报分的权重
  last_summary_key: null  # 上次朝账摘要 loc_key（账簿用）
  council_queue: []       # ④ 段发言顺序 char_id[]
  council_index: 0
  council_log: []         # { char, spoke, topic_key?, stance?, mode? }
  policy_draft: {}        # 建言倾向累积分；供 ⑤ 定调
```

朝账日结束时：

1. `cycle_index += 1`  
2. `days_until_next = 7`  
3. `report_score = 0`（新周期重计）  
4. 清空并发放新 `weekly_tasks`  
5. 清空 `council_*` 与 `policy_draft`（或摘要写入 `last_summary_key`）

## 6. 与事件类型的关系

| 事件前缀 | 角色 |
|---|---|
| `M*` | **朝账场次壳**：负责五段式流程与旁听/汇报 UI |
| `E*` | **剧情结算权威**：恩怨、职级、旗标仍在 E 文档定义 |
| `F*` | 降职/开除可在朝账 ③ 段宣布（如 `F002`） |

原则：`M002` 播 E004/E006 的对白与 effect，**不重复发明** grudge / trust 结算。

## 7. Effect 扩展

| op | 语义 |
|---|---|
| `assign_weekly_tasks` | `ids: [task_*]` 写入 `run_meeting.weekly_tasks` |
| `add_meeting_report` | `value: int` 加本周 `report_score`（封顶 100） |
| `set_meeting_tier` | `value: listen\|report\|decide` |
| `init_council_queue` | `ids: [char_*]` 生成本局 ④ 段顺序 |
| `record_council_speech` | 记发言/沉默/附议 |
| `add_policy_draft` | `key`, `value` 累加定调倾向 |
| `set_meeting_segment` | `value` 议场切段（仅 DomainBus，表现层） |

建言细则：[`诸人建言.md`](诸人建言.md)。
